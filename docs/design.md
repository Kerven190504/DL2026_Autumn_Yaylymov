# Проектирование — «Атлас», географическая викторина

## 1.1. Пользовательские сценарии

1. **Как игрок**, я хочу выбрать тему (столицы / достопримечательности /
   природные объекты / всё сразу) и режим («10 вопросов» или «без
   ограничений»), чтобы игра соответствовала моим интересам и
   доступному времени.
2. **Как игрок**, я хочу кликнуть на карте мира в том месте, где, по
   моему мнению, находится показанный объект, и сразу увидеть, насколько
   я ошибся (расстояние, правильную точку и полученные очки), чтобы
   учиться на ошибках по ходу игры.
3. **Как игрок**, я хочу увидеть свой итоговый счёт и попасть в таблицу
   лидеров под своим именем, чтобы сравнить результат с другими и
   вернуться сыграть снова, если захочу его улучшить.

## 1.2. Функциональные требования

**Обязательные:**
- Показ вопроса (текст) и интерактивной карты мира.
- Клик по карте отмечает точку-предположение; повторный клик до
  подтверждения переставляет точку.
- Подтверждение ответа отправляет координаты на сервер и получает
  расстояние до правильной точки, начисленные очки и правильное
  местоположение.
- Начисление очков по убывающей от расстояния шкале (чем точнее — тем
  больше очков).
- Переход к следующему вопросу без перезагрузки страницы.
- Индикация прогресса («вопрос X из Y») и текущего счёта.
- Режим «серия из 10 вопросов» с итоговым экраном по завершении.
- Таблица лидеров (сохраняется на сервере, переживает перезапуск).

**Опциональные (реализованы):**
- Подсказка (регион объекта) с штрафом к очкам за вопрос.
- Таймер на вопрос (25 сек.) для динамики; при истечении время
  засчитывается промах вместо блокировки игры.
- Режим «бесконечная» игра без фиксированного числа вопросов.
- Тематические подборки вопросов (фильтр по категории).
- Место игрока в общем рейтинге сразу после отправки результата
  («вы на N-м месте из M»), без похода в отдельную таблицу.
- Возможность игрокам предлагать свои локации, выбирая их тему
  (столицы/достопримечательности/природные объекты) — они сразу
  становятся частью игры наравне с кураторскими, с прозрачным
  счётчиком «сколько из этой темы добавили игроки» (`community_count`).

**Опциональные (не реализованы, оставлены как развитие продукта):**
- Полноценная модерация предложенных локаций — сейчас только базовый
  фильтр явного треша в тексте (`backend/moderation.py`), без очереди
  на проверку человеком (см. «Известные ограничения» в README.md).
- Аккаунты пользователей с историей результатов между сессиями.
- Живой командный режим в духе Kahoot (PIN/QR-код для входа, команды,
  один хост запускает раунд для всех). Сознательно не взято в эту
  итерацию: это не расширение текущей функции, а другой продукт —
  требует WebSocket-сервера, ролей хост/игрок и синхронизации раундов
  между устройствами в реальном времени, тогда как вся текущая
  архитектура (сессия в памяти одного процесса, один игрок на сессию)
  рассчитана на одиночную игру. Технически осуществимо, но это
  отдельный, при этом немаленький проект, а не доработка викторины.

## 1.3. Проектирование API

Аутентификация не используется — идентификация игрока в рамках одной
партии происходит через `session_id`, который выдаётся при старте игры
и живёт в памяти процесса сервера.

| Метод | Путь | Параметры запроса | Ответ |
|---|---|---|---|
| GET | `/api/categories` | — | `[{value, label, count, community_count}]` — count включает и кураторские, и предложенные игроками локации; community_count — сколько из них от игроков |
| POST | `/api/quiz/start` | `{mode: "classic"\|"endless", question_count: int, category: string}` | `{session_id, question: {question_id, prompt, category, index, total_questions}}` |
| POST | `/api/quiz/{session_id}/hint` | — | `{region, penalty_applied}` — регион текущего объекта, включает штраф к очкам за этот вопрос |
| POST | `/api/quiz/{session_id}/answer` | `{lat: float, lng: float}` | `{distance_km, score, total_score, correct_name, correct_lat, correct_lng, hint_used, is_finished, next_question}` |
| GET | `/api/quiz/leaderboard?limit=50` | query `limit` | `[{player_name, score, questions_count, mode, created_at}]` |
| POST | `/api/quiz/{session_id}/leaderboard` | `{player_name: string}` | `{rank, total}` — место в общем рейтинге и число всех результатов |
| POST | `/api/locations/suggest` | `{name, category, lat, lng, region?}` | `{id, prompt}` — сразу становится частью выбранной темы наравне с кураторскими локациями |

Ошибки возвращаются стандартным для FastAPI образом:
`{"detail": "человекочитаемое сообщение"}` с кодами 400 (некорректный
запрос, например пустая категория) и 404 (сессия не найдена/истекла).

## 1.4. Модель данных

**Локация (справочник в коде сервера, `backend/data.py`)**

| Поле | Тип | Описание |
|---|---|---|
| id | string | уникальный идентификатор |
| category | enum(`capital`,`landmark`,`nature`) | тематика |
| name | string | отображаемое название после ответа |
| prompt | string | текст вопроса |
| lat, lng | float | правильные координаты |
| region | string | регион, выдаётся как подсказка |

**Предложенная локация (SQLite, таблица `user_locations`)**

| Поле | Тип | Описание |
|---|---|---|
| id | INTEGER | автоинкремент, в игре виден как `user-<id>` |
| name | TEXT | название, которое ввёл игрок |
| prompt | TEXT | вопрос («Где находится {name}?») |
| lat, lng | REAL | координаты, выбранные кликом по мини-карте |
| region | TEXT | регион для подсказки (необязательное поле) |
| created_at | TEXT | когда добавлена |

Играбельна сразу после отправки, но живёт в собственной теме «От
игроков» — не смешивается со встроенным банком вопросов (см. 1.5).

**Игровая сессия (в памяти процесса, `backend/app.py: SESSIONS`)**

| Поле | Тип | Описание |
|---|---|---|
| mode | enum(`classic`,`endless`) | режим игры |
| category | string | выбранный фильтр тем |
| remaining_pool | list[string] | id ещё не заданных вопросов |
| current_question_id | string | текущий вопрос |
| answered_count | int | сколько вопросов уже отвечено |
| total_questions | int \| null | null для режима `endless` |
| score | int | накопленный счёт |
| hint_used_current | bool | брал ли игрок подсказку на текущий вопрос |

**Запись таблицы лидеров (SQLite, `backend/db.py`)**

```json
{
  "id": "INTEGER PRIMARY KEY",
  "player_name": "TEXT",
  "score": "INTEGER",
  "questions_count": "INTEGER",
  "mode": "TEXT",
  "created_at": "TEXT (ISO datetime)"
}
```

Игровая сессия хранится в памяти, а не в БД: она недолговечна
(минуты), не обязана переживать перезапуск сервера, и хранение в
памяти сильно упрощает код для учебного проекта. Таблица лидеров,
наоборот, обязана быть постоянной — она в SQLite-файле.

## 1.5. Ключевые технические решения

- **Бэкенд: Python + FastAPI.** Быстро описываются типизированные
  эндпоинты через Pydantic-модели (что само по себе документирует
  API), встроенная Swagger-документация на `/docs`, лёгкий запуск на
  Linux и Windows без дополнительной сборки.
- **Хранилище: SQLite** — для одиночного инстанса сервера этого более
  чем достаточно, не требует установки отдельной СУБД, файл БД
  переносится вместе с проектом.
- **Фронтенд: React + Vite.** Быстрый старт разработки, широкая
  экосистема, react-leaflet даёт готовую интеграцию карты с React без
  написания обёртки над Leaflet вручную.
- **Карта: Leaflet, без API-ключа.** Бесплатно, в отличие от Google
  Maps, чего достаточно для викторины — не нужны Street View или
  геокодирование адресов. Тайл-провайдер менялся по ходу разработки
  (см. ниже) ровно потому, что это требование проверялось на практике,
  а не принималось один раз на старте.
- **Карта: один настоящий тайл-слой под все три темы, с оверлеем для
  двух из них.** Это не оформление, а часть игровой механики: подпись
  на карте — либо подсказка (портит вопрос), либо опора (учит).
  Базовый слой — Esri `World_Physical_Map` (физическая карта рельефа,
  без единого слова текста и без политических границ) под все три
  темы. Поверх него опционально — Esri
  `Reference/World_Boundaries_and_Places_Alternate`, официально
  документированный как прозрачный оверлей именно для таких
  физических/рельефных подложек (границы стран + названия городов):
  - *Столицы* — только физическая подложка, без оверлея. Название
    города на карте было бы прямой подсказкой ответа.
  - *Достопримечательности* и *Природа* — подложка + оверлей границ и
    названий. Знание "это Франция" не называет конкретный памятник или
    объект напрямую, зато даёт систему координат — обучающий эффект,
    которого не было бы у немой карты.
  Прошли три итерации до этого: сначала тайлы CARTO (бесплатные без
  ключа) — провайдер без предупреждения ввёл обязательную
  авторизацию, и карта стала показывать водяной знак "API KEY
  REQUIRED"; затем собственный встроенный GeoJSON-рендер (чтобы вообще
  не зависеть от внешнего тайл-сервера) — он решал проблему текста, но
  выглядел плоско и имел баг с рендер-швами на границе old/new
  размеров контейнера (Leaflet не пересчитывал bounds после довёрстки
  CSS-грида). Нынешний вариант — тоже внешние тайлы, но давно
  стабильный публичный сервис Esri с историей такого использования, и
  с явно документированным назначением слоёв (это не тот же риск, что
  был у CARTO: там подписи на изображении приходили от любого выбранного
  "стиля" без разделения, здесь база и оверлей — разные сервисы с
  явно описанным контрактом).
- **Набор данных: 100+ кураторских локаций, проверяемых тестами.**
  41 столица, 33 достопримечательности, 29 природных объектов, с
  двуязычными полями. Целостность (уникальные id, полные переводы,
  координаты, отсутствие ответов ближе 30 км внутри темы) закреплена в
  `backend/tests/test_data.py` — ручной ввод такого объёма иначе
  незаметно копит ошибки.
